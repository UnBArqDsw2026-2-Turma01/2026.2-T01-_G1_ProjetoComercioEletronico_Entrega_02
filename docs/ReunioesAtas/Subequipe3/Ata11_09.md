## 3. Discussões

### Diagrama de Classes

* Joaquim Neto apresentou o diagrama de classes atualizado, que precisou ser migrado para uma nova plataforma gratuita devido a limitações de pagamento do site utilizado anteriormente.


* O projeto conta com dezesseis classes selecionadas, abrangendo o paradigma de orientação a objetos, com herança, polimorfismo e composição.


* Dados cadastrais como CPF, e-mail e telefone foram modelados como classes validadoras específicas para otimização.


* A classe de preço foi definida para armazenar valores em centavos, com o objetivo de evitar erros de arredondamento em operações de comércio eletrônico.


* Foi explicada a cardinalidade: um cliente pode possuir de zero a vários endereços, mas o endereço deve estar obrigatoriamente vinculado a um cliente.



### Diagrama de Casos de Uso

* Pedro apresentou o diagrama desenvolvido por Júlia, estruturado sob a perspectiva geral do mercado.


* O fluxo cobre a busca por produtos, login, processamento de pagamento, envio, ações de transportadora e gerenciamento de estoque pelo vendedor.


* Joaquim sugeriu adicionar um caso de uso de devolução de mercadorias pelos compradores devido ao alto índice dessa ocorrência, o que foi rapidamente aceito por Júlia.


* Pedro levantou também a possibilidade de incluir formas alternativas de autenticação, como o login via Google.



### Diagrama de Implementação

* Pedro Henrique exibiu o diagrama com foco na arquitetura de hardware e servidores, elaborado por meio de engenharia reversa da infraestrutura do Mercado Livre.


* Foi modelado um servidor nacional em São Paulo (próximo a Guarulhos) que recebe a requisição do computador pessoal, evitando operadoras terceirizadas para garantir mais agilidade.


* A arquitetura engloba serviços da Amazon Web Services (AWS), como Amazon Route 53, Amazon CloudFront e Amazon S3 para arquivos com criptografia.
